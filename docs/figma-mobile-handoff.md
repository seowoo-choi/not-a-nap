# NOT A NAP — 모바일 Figma V11 직접 돌봄 핸드오프

> 기준: 2026-07-27 배포 코드 `3aef7c7`
> 목적: 실제 Unity의 직접조작 문법과 완성 합성 이미지를 기존
> `MOBILE_QA_STORYBOARD_V6_CODE_SYNC_*` 보드 한 장에 동기화한다.
> 판정 원본: `Assets/Scripts/Core`; Figma는 판정하지 않고 상태와 입력만 표현한다.

## 1. V11 핵심 원칙

- 아기가 화면의 주인공이다. 세로 PLAY에서 아기 아트 기준 크기는 720px이며, 아기 무대가
  주요 가용 높이의 66–72%를 차지한다.
- 하단 행동 버튼 덱, `살펴보기/돌보기/수유 준비` 탭, 컨텍스트 칩을 PLAY에서 제거한다.
- 아기의 몸과 방의 소품을 직접 터치한다. 터치 영역은 넓고 투명하며, 지금 권장되는 한 곳만
  따뜻한 펄스와 반짝임으로 보인다.
- 제품 PNG를 아기 위에 얹지 않는다. 아기띠, 안기, 토닥임, 수유, 쪽쪽이는 아기·보호자 손·
  소품·자세가 한 장면으로 완성된 합성 이미지로 표시한다.
- 숨은 `ActiveCause`는 노출하지 않는다. Core가 허용한 행동과 관찰된 신호만 반짝인다.

## 2. 세로 PLAY 구조

```text
시계 / 새벽까지 남은 시간
신호 리본                         우리 집 새벽 동선
크고 중앙에 놓인 아기 + 직접 터치 영역
방 안의 실제 소품(백색소음기·쪽쪽이·아기띠 등)
연속 수면 / 보호자 체력 / 마음의 여유
짧은 결과 문장
```

- 상태 카드와 결과 문장은 하단에 붙이고 아기와 소품을 덮지 않는다.
- 지도는 우상단의 보조 정보다. 아기나 말풍선과 겹치면 축소하거나 숨긴다.
- 흰 말풍선, 화면 중앙의 검은 버튼, 제품을 아기 몸에 붙인 오버레이를 사용하지 않는다.

## 3. 아기 직접 터치 계약

| 터치 영역 | Core 행동 | 화면 피드백 |
|---|---|---|
| 입·손 | `CheckHungerSignals`, `FeedPreparedBottle`, `Pacifier` | 신호 확인 또는 준비 상태에 따라 한 행동만 권장 |
| 등·어깨 | `Pat` | 손이 보이는 느린 3회 토닥임 |
| 가슴·상체 | `Hold`, `ToggleCarrier` | 목과 등을 받친 안기 또는 아기띠 해제 |
| 기저귀 | `CheckDiaper`, `ChangeDiaper` | 확인 전에는 원인 누설 없음 |
| 팔다리 | `CheckLimbRelaxation` | 힘 빠짐과 호흡을 함께 관찰 |
| 매트리스 | `Laydown` | Held + 수면 조건일 때만 노출 |

터치 영역 자체에는 테두리와 라벨을 상시 표시하지 않는다. 포인터가 올라오거나 권장 영역일
때만 짧은 라벨을 보인다. 접근성용 터치 면적은 실제 보이는 아기보다 넓게 둔다.

## 4. 완성 합성 이미지와 모션

`Assets/Resources/Art/Baby/Interaction/`의 20개 합성 스프라이트가 단일 기준이다.

| 행동 | 길이 | 필요한 완성 상태 |
|---|---:|---|
| 토닥이기 | 3.4초 | 손 접근 / 접촉 / 두 번째 토닥 / 편안한 마무리 |
| 품에 안기 | 3.2초 | 목 받치기 / 들어 올리기 / 품에 밀착 / 살랑이는 마무리 |
| 아기띠 | 2.8초 | calm / fuss / cry / sleep 장착 상태 |
| 준비한 분유 수유 | 3.4초 | 젖병 접근 / 입에 닿음 / 삼킴 / 안정 |
| 쪽쪽이 | 2.8초 | 방 소품 / 입가 접근 / 수용 또는 거절 / 안정 |

Figma 키프레임도 제품과 아기를 따로 겹치지 않고 완성 상태 이미지를 한 장씩 배치한다.
토닥임은 손이 명확히 보여야 하며 1초 안에 끝나는 연출로 축약하지 않는다.

## 5. 방 소품 직접조작

### 아기방

- 쪽쪽이는 소지했다면 방 안 소품으로 항상 보인다. 사용 가능할 때만 펄스한다.
- 아기띠는 미착용일 때 방 소품으로 보이며 터치하면 착용 완성 이미지로 전환한다.
- 백색소음기와 베이비 모니터도 기계 자체를 터치한다.

### 주방

- 아기를 안고 왔으면 상단 아기 무대와 하단 조리대를 분리해 서로 겹치지 않는다.
- 분유통 → 젖병 → 식힘 물 순으로 실제 오브젝트를 터치한다.
- 다음에 필요한 오브젝트 하나만 반짝인다.
- 젖병 내용물은 상태로 확인할 수 있어야 한다.

| 상태 | 젖병 시각 |
|---|---|
| 준비 전 | 투명하고 비어 있음 |
| 물 준비 | 낮은 수위의 맑은 물 |
| 혼합 완료 | 따뜻한 분유색이 70%가량 채워짐 |
| 식힘 완료 | 같은 수위 + 차분한 색/완료 광택 |
| 수유 완료 | 다시 비어 있음 |

평상시 젖병은 소독 완료 상태다. `BottleFoundUnsanitized` 돌발에서만 소독 단계를 보인다.

## 6. QA 프레임

기존 PLAY 35장의 상태 ID는 Core 회귀 검사용으로 유지하되, V11 보드에는 다음 직접조작
키프레임을 별도 생성한다.

1. `DIRECT_BABY_DEFAULT` — 큰 아기와 추천 터치 한 곳
2. `DIRECT_PAT_CONTACT` — 손이 등에 닿은 중간 프레임
3. `DIRECT_HOLD_FINAL` — 품에 확실히 안긴 완성 프레임
4. `DIRECT_CARRIER_CALM/FUSS/CRY/SLEEP` — 아기띠 4상태
5. `DIRECT_PACIFIER_PROP/APPROACH/ACCEPT/REJECT` — 쪽쪽이 전 과정
6. `DIRECT_KITCHEN_EMPTY/WATER/MIXED/COOLED/READY` — 눈으로 읽는 젖병 상태
7. `DIRECT_FEED_CONTACT` — 손·젖병·아기가 합쳐진 수유 중간 프레임

각 프레임은 1080×1920 실제 QA 화면이어야 한다. 작은 도식만으로 완료 처리하지 않는다.

## 7. 플러그인 동기화 결과

`figma-plugin/code.js`는 기존 최신 CODE_SYNC 보드를 제자리에서 갱신한다.

- `CODE_SYNC_UNITY_PRESENTATION_V11`
- `CODE_SYNC_SETUP_PRESENTATION_V11`
- `_ACTION_MOTION_SPEC_V11`
- `CODE_SYNC_REFLECTION_CONTRACTS_V10` — 판정·일지·엔딩 계약은 그대로 유지

V9의 버튼 덱과 행동 탭은 V11 화면 계약에서 폐기한다. Core의 `V2ActionId`와 밸런스는
변경하지 않고 입력 경로와 Presentation만 직접조작으로 바꾼다.
